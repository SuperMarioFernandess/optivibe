# 00 — Входной приёмочно-обзорный документ (Review & Onboarding Guide)

**Проект:** OptiVibe — цифровой двойник волоконно-оптического датчика (ВОД) вибрации.
**Кому:** стороннему опытному физику, получившему репозиторий и физбазу.
**Что это:** единый **навигационный** документ приёмочного слоя. Он **не выводит физику заново** —
он связывает существующие артефакты (физбаза 00–08, слой `docs/theory/` 01–06, решения 06/13,
код и тесты) сквозной тройной ссылкой **«вывод → решение → тест»** и даёт воспроизводимый
маршрут «проверь сам». Первоисточник любого числа — физбаза 00–08 и код; здесь только карта и
приёмка (принцип слоя — 15 §9.3, `docs/theory/README.md`).

**Как читать.** Разделы 1–5 отвечают на четыре вопроса физика по порядку: *что за модель* (§2) →
*верна ли модель* (§3) → *верен ли ей код и сходятся ли расчёты* (§4) → *как этим пользоваться*
(§6) → *каковы границы перед реальным датчиком* (§7). Ядро — §5 «Проверь сам».
Обозначения — по 01; идентификаторы/пути — как в коде (`main`, HEAD `6320f57`).

## 0. Рамка зрелости (прочитать первым)

Три уровня согласия по словарю 17 §3. Честный статус на момент документа:

| Уровень | Что сравнивается | Статус | Где смотреть |
|---|---|---|---|
| **L1** — код ↔ аналитика | функция кода ↔ замкнутая формула базы 02/03/05/07 | **пройден** | план **18** (golden-инвентарь, дыры G1–G12) |

времени (`docs/theory/README.md`; план 20).

**Что изменилось после серии M-01/M-02/M-12/M-10/M-09 (2026-07-12/13).** Три бывшие «дыры модели»

## 2. Физическая модель — что моделируется *(цель a: понять модель)*

Геометрия: волокно-консоль (заделка `z=0`, свободный торец `z=L`); свет по волокну → воздушный
зазор `A` → выпуклый отражатель (v1 — цилиндр) → возврат в волокно → фотодетектор. Состояние
торца — вектор интерфейса `q_tip = (Δx, Δy, Δz, θx, θy)`, `Δz` — изменение зазора (06 R-04; СК и
знаки — 01). Целевая ось `x` (плоскость кривизны цилиндра), `y` — «плоская», образующая ∥ `y`
(06 R-11).

Цепочка сигнала и её якоря (вывод — theory; репер — база; решение — 06):

| Звено | Ключевой результат | Вывод (theory / база) | Решение (06) |
|---|---|---|---|
| Механика консоли | `f₁ ≈ 100/L²` кГц; `H_lat^QS ≈ 0.0384·L⁴` нм/g; жёсткая связь `θ = 1.377·Δ/L` | `01_sensing_element`; 02 §8 | R-07, R-10 |
| Динамика | `\|D(f)\|`: `f→0 ⇒ 1`, `f=f₁ ⇒ Q`; режим **внерезонансный** (квазистатическая полка) | `01_sensing_element`; 05 | R-21 |
| Оптика (обратная связь) | `η(Δx,Δy,Δz)`; `∂η/∂Δy = 0` в 1-м порядке; `∂η/∂Δz` — трёхчленная форма, `≈ −7.9·10³` м⁻¹ | `02_optical_path`; 03 §e (v1.2), 04 §4 (v1.1) | **R-41** |
| Модель сигнала | интенсивностная `S = ℛP(R₁ + ρη)`; маршрут 2 (когерентный смыв, `V<0.03`) | `03_photodetection`; 03, 05 | R-13, R-14, **R-19** |
| Сквозная чувствительность | `s_target(f) = ℛ·P·ρ·(∂η/∂Δx)_эфф·H_QS·\|D(f)\|` | `05_software_firmware`; 05 §2 | R-19, R-20 |
| Шум/предел | `NEA(f) = i_n/\|s_target\|`, квадратурно с `NEA_th`; «ускорительная» масса `M_a ≈ 0.58ρSL` | `03_photodetection`; 07 §1–§2 | **R-22, R-25** |
| Направленность | анизотропия `≈ L/(1.377·R_c)` → перекрёстная ось | `02_optical_path`; 04 §6 | R-43 |
| Семейство A/B/C/D | мастер-закон `NEA ∝ f_max²`; эталон численных примеров — **B** (`L=2.0` мм, `R_c=31` мкм, `A=31` мкм, `Δx₀=0.992` мкм) | `usage_modes`; 08 | R-42 |

Эталонная точка численных примеров во всём слое — **вариант B** (`docs/theory/README.md`); числа в
блоках воспроизводятся из моделей кода, не из памяти.

## 3. Корректность физической модели: уровень **L2** *(цель a/b)*

L2 проверяет **согласованность модели с собой**: производные соотношения 17 §2, предельные случаи
семейства форм, межмодельные тождества. Принцип: метрики **не независимы**; рассогласование между
связанными метриками трактуется как сигнал ошибки, а не «две оценки» (19 §1). Навигатор — 19 §2.1–2.2.
Примеры доказательных точек (все — тройной ссылкой):

> **Как цитируются тесты.** Ниже и далее приводится **полный node-id** `файл::имя_функции` — ровно то,
> что принимает `pytest` (`uv run pytest "tests/…::test_…"`). Имена всех тестов начинаются с `test_`;
> прежняя запись без этого префикса работала только через `-k` и приводилась к полному виду
> (актуализация 2026-07-13).

- **Мастер-закон `NEA ∝ f_max²`** — связка `NEA∝L⁻⁴` и `f₁∝1/L²`.
  Вывод 08 (R-31) → решение **19 V19-L2-04** → тест `tests/test_model_vv_l2.py::test_golden_nea_master_law_fmax_squared`.
- **Межмодельные тождества по плоскостям** — `cylinder(силовая) ≡ sphere(x)`; `cylinder(плоская) ≡ plane`,
  `sphere R_c→∞ → plane`. Вывод 03 §c′/§d (канонизирован **R-43**) → решение 19 V19-L2-05/06 →
  тесты `tests/test_model_vv_l2.py::test_golden_cylinder_planes_match_sphere_and_plane` (rtol `1e-12`),
  `tests/test_model_vv_l2.py::test_golden_sphere_infinite_radius_matches_plane` (`1e-3`).
- **Факторизация `∂η/∂Δz`** — трёхчленное разложение как тождество.
  Вывод 04 §4 v1.1 (**R-41**, аннулирует прежнее `−2·10⁴` м⁻¹) → решение 19 V19-L2-07 →
  тест `tests/test_model_vv_l2.py::test_golden_dz_slope_three_term_decomposition` (тождество `1e-6` + репер `−7.9·10³` м⁻¹, 5 %).
- **Пределы `\|D(f)\|`** — `f→0 ⇒ 1`, `f=f₁ ⇒ Q` (точно), пик `= Q×QS`.
  Вывод 02/05 → тесты `tests/test_mechanics_modal.py::test_limit_dynamic_factor_dc_is_unity`,
  `tests/test_mechanics_modal.py::test_limit_dynamic_factor_at_resonance`,
  `tests/test_mechanics_modal.py::test_golden_resonant_peak_is_q_times_qs`.
- **Анизотропия / перекрёстная ось** — `≈ L/(1.377·R_c)` (34.86× @3 мм), остаток `∝ Δy²`.
  Вывод 04 §6 → тесты `tests/test_optics_cylinder.py::test_golden_anisotropy`,
  `tests/test_optics_cylinder.py::test_golden_cross_axis_residual_quadratic`.
- **Вычислимая `Q(L)` (M-02, R-47/R-48)** — гидродинамическая функция Sader ⊕ заделка ⊕ внутренние потери;
  немонотонность с пиком `Q≈2611` при `L≈2.05 мм`. Вывод `01_sensing_element` §3.8; база 02 §5, 07 §2.3 →
  тесты `tests/test_mechanics_damping.py` (реперы `Γ`, `Q_air`, `Q_anchor`, `Q_total(L)`, пик).
- **Тепловой пол `NEA_th` (M-12, R-52…R-54)** — тождество двух маршрутов отнесения
  `√S_F/(0.375·m_tot) ≡ √(4k_BTω₁/(Q·M_a))`, показатель `∝L^{−3/2}` при фиксированной `Q`.
  Вывод `03_photodetection` §3.4 → тесты `tests/test_mechanics_thermal.py`.
- **Форма линии и смыв (M-10, R-55/R-56)** — `V(A)` из Винера–Хинчина; тождество
  `A_min^L·L_c = (A_min^G)²`; форм-факторы `κ` (2 / 1.3286 / 0.6366).
  Вывод `02_optical_path` §3.1–§3.2 → тесты `tests/test_optics_source.py`.

**Известное ограничение L2 (не дефект):** сквозные L2-проверки восстановления существуют только для
цилиндра — `standard`-инверс **cylinder-only** (граница G9, см. §7); для sphere/plane/wedge L2 держится
на уровне `η` (19 §2.4).

## 4. Корректность кода и сходимость: уровень **L1** *(цель b)*

L1 сверяет каждую функцию с замкнутой формулой базы. Навигатор — **18 §3** (таблица «метрика 17 §1 →
тест», статусы по легенде 18 §3: пройдено / закрыто-патчем / через-S-02 / не-моделируется). Допуски L1 (17 §3 / 11 §7): механика/оптика ≤ 2–5 %, шумы ≤ 10 %
(PSD sim↔analytic ≤ 15 %), пределы — точно, `s_target` умолчаний v1 — **бит-в-бит**.

Golden, пиннящие именно **формулы базы** (правило 18 §5(г): golden ссылается на замкнутую формулу
или стандарт, а не на «текущий выход кода»):

- **Таблица зон ISO 10816-3** — все 4 класса, конвенция границы `v ≤ предел → нижняя зона`.
  Стандарт → 18 G1 → `tests/test_dsp.py::test_iso_zone_boundaries_match_published_table`.
- **THD ↔ аналитическая 2-я гармоника** `HD2 = \|η″\|·d/(4\|η′\|)` (Тейлор 2-го порядка).
  Вывод 03 §5 → 18 G4 → `tests/test_optics_cylinder.py::test_golden_thd_matches_analytic_second_harmonic` (2 %, факт 0.3 %).
- **Тождество динамического диапазона** `DR = 20·log₁₀(FS·g₀ / NEA·√B)` для A/B/C/D.
  17 §1 → 18 G2 → `tests/test_analysis.py::test_analytic_point_dynamic_range_identity` (rel `1e-12`).
- **Полнополосный `NEA·√B ↔ ∫NEA(f)²df`** + пиннинг **двух** конвенций полосы (найквистова у
  `NeaBudget` vs проектная у `AnalyticPoint`).
  07 → 18 G3 → `tests/test_analysis.py::test_nea_full_band_consistent_with_spectrum` (≤ 10 %).

**Бит-идентичность A/B/C/D** — контракт `tests/data/resolved_variants_golden.json` (полный `model_dump`
разрешённых вариантов). Правило: меняется **только осознанно и аддитивно**; любое изменение
существующих чисел = смена контракта с записью в 13 (18 §5). Якорь обратного тракта
`static+ideal+plateau ≡ v1` (`s_target = −1.93·10⁻⁷`) — бит-в-бит, `tests/test_sensitivity.py::static_default_is_bit_identical_to_v1`.

**Метрики на реальных данных** — роль «анализатор реального выхода прибора» (запись фототока →
метрики 17 §1 минуя forward), реализована на синтетике (18 G5 закрыт, SW-52):
`tests/test_analysis_instrument.py` (round-trip forward→файл→`analyze`), `tests/test_io_records.py`
(единицы V→A, метаданные). Реальные записи Э-0/Э-3 добавляются аддитивно после стенда.

> **Замечание о счёте golden.** `pytest -m golden` даёт **159** (см. §5). Наивный grep декораторов даёт
> меньше — часть модулей помечена `pytestmark` на уровне файла; методика счёта разъяснена в 18 §2. При
> сверке пользуйтесь маркером, а не grep.

## 5. Корешок проверяемости — «проверь сам» *(ядро)*

Ровно тот маршрут, что проходит координация на каждой приёмке. **Корректность проверяема, а не
декларируется.** Ниже — (а) команды рецензенту с ожидаемыми числами (из 18/14) и (б) логи, реально
**воспроизведённые координацией** при подготовке документа, — чтобы рецензент сравнил своё окружение
с эталоном.

### 5.1 Восстановление и ворота

```bash
git clone https://github.com/SuperMarioFernandess/optivibe
cd optivibe && git checkout 6320f57
uv sync --locked --python 3.11 --extra dev --extra gui --extra io-formats
export QT_QPA_PLATFORM=offscreen        # pytest-qt/GUI headless (18 §5)

uv run ruff check
uv run ruff format --check
uv run mypy
uv run pytest --cov=optivibe            # полный набор
uv run pytest -m golden                 # подмножество golden
sha256sum tests/data/resolved_variants_golden.json
```

Пин Python **3.11** обязателен: свежий numpy тянет стабы 3.12-синтаксиса, ломающие `mypy` под 3.11 —
`mypy`-истина именно CI на 3.11 (18 §5 «Риски окружения»).

**Про `gui`-extra (уточнено `SW-69`, 2026-07-30).** Охват `mypy` задан конфигом `files = ["src"]` и
равен **105 файлам в обоих окружениях** — и с `--extra gui`, и без него; число файлов от extras не
зависит. Деградирует **строгость**: без установленного PySide6 действует

## 6. Как пользоваться: CLI и GUI *(цель c)*

**CLI** — точка входа `optivibe` (`pyproject.toml [project.scripts]`), **шесть** подкоманд
(`src/optivibe/cli/main.py`): `run`, `report`, `sweep`, `analyze` (роль S-02), `compare` (стенд
сравнения цепочек ЦОС, `SW-73`) и `ingest` (применение измеренных артефактов к композиции, `SW-63`).
Сценарий — YAML (`{name, variant∈{A,B,C,D,proto_poc}, excitation, stages, dsp, seed, output}`;
13 SW-11). Коды выхода: `0` — успех, `2` — ошибка входа. Приёмочные доминанты (полный набор
регресс-защищён — 18 §5): `hello 120`, `replay_tdms 50`, `cross_axis 240`, `resonance_sweep 5005`,
`analyze 120`, `proto_poc_2f 240`. Продуктовое описание — `docs/manual/` (модули `ui_cli`, `ui_data`,
`ui_ingest`, `ui_compare`), API — `docs/reference.md`. **[реализовано]**

**GUI** — десктоп PySide6 + PyQtGraph (`optivibe-gui`), **шесть** вкладок верхнего уровня
(Live / Report / Sweeps / Monte-Carlo / **Compare** / Physics); редактируемая композиция подсистем
(форма на подсистему, пресет + SI-overrides), панель «Эксперимент: цепочка ЦОС» (все точки выбора
`DspOptions` с тегом применимости батч/поток/оба и вычисляемым вердиктом `verified`/`experimental`),
вкладка «Физмодели/справка» (лёгкие `f₁(L)`/`\|H_lat(f)\|`/`η(Δx)` inline, тяжёлый `NEA(f)` — через
воркер). Интерфейс двуязычный (RU/EN, живое переключение), с темой и per-tab справкой (`SW-65`/`SW-66`).
Вкладка Live работает в двух режимах: разовый прогон и **живой поток** поверх причинного слоя
(`SW-72`) с обязательным провенансом `warmed`/пропуски на экране. Тяжёлые расчёты — в
`QThread`-воркерах, GUI-поток не блокируется; **headless-паритет:** любой прогон доступен и через
`cli` (13 SW-06/SW-13/SW-45; 14 §1). Продуктовое описание — `docs/manual/` (`ui_gui`, `ui_live`,
`ui_compare`). **[реализовано]**

**Импорт данных.** Три роли: (а) **replay-вход** — эталонный канал ускорения через загрузчики
`LOADER_REGISTRY` (csv, wav, tdms, uff, mat, hdf5; 13 SW-08); (б) **анализ выхода прибора** —
`optivibe analyze` (роль S-02): запись фототока → метрики минуя forward; (в) **ввод измеренных
параметров** — `optivibe ingest` (S-13, `SW-63`): характеризационный артефакт фазы 0 (CSV + обязательный

Замечание о зрелости (в): реализован **тракт**, а не данные — измеренных артефактов пока нет (§0, §7). (реальных записей прибора пока
нет — только синтетические round-trip'ы; §7).

## 7. Границы применимости и зрелость *(цель d)*

**Границы ядра (зафиксированы как решения, не баги):**

- **G9 — `standard`-инверс cylinder-only.** Калиброванная обратная задача (static/operating_point/
  nonlinear) реализована только для цилиндра (`CylinderOpticsModel`); sphere/plane/wedge прогоняются со
  `stub`-DSP или обходятся явной калибровкой `measured`/`bench`. Для не-цилиндра с источником `model`
  анализатор **громко отказывает** (не молчит). 18 G9, 14 §1, 19 §2.4.
- **~~MG-1~~ — ЗАКРЫТА (M-12, R-52…R-54).** Тепловой пол `NEA_th=√(4k_BTω₁/(Q·M_a))` реализован
  (`mechanics/thermal.py`) и включён **четвёртой ветвью** бюджета NEA в ускорительном домене
  (`dsp/nea.py`, `analysis/nea_budget.py`, `include_thermal=True` по умолчанию). Остаточные
  **осознанные** ограничения ветви (R-54): (а) синтетический **временной ряд** детектора теплового
  движения **не содержит** — полон аналитический бюджет, не синтетика; (б) тракт **измеренных** записей
  (`nea_from_psd`) ветвь намеренно **не добавляет** (реальный фототок уже содержит броуновское движение —
  иначе даблкаунт). Частотная форма: сокращение резонанса — точное при любой модели потерь; плоскостность
  — вязкое приближение, и **нижняя декада варианта A** при гистерезисном угле потерь кремнезёма может
  оказаться тепло-лимитированной (**M-14**, открытая физика; R-53).
- **Вакуум — идеализация (M-13).** `vacuum: true` даёт `Q_air = ∞`; реальное разрежение проходит три
  кнудсеновских режима, `Q_air(p)` не смоделирована ⇒ использовать `vacuum: true` для количественных
  выводов **запрещено** до M-13 (R-49). Базовая среда всего семейства — **воздух** (R-49).
- **Граница верифицированного — дефолтная цепочка ЦОС (`SW-73`).** Планы 18/19, golden-набор и
  бит-идентичность поток↔батч покрывают `DspOptions()` и только её. Стенд сравнения открывает
  альтернативы (шесть окон, три интегратора — включая причинный `leaky`, выключаемая интерполяция
  пика), но любое отклонение от дефолта делает прогон **экспериментом**: вердикт
  `verified|experimental` **вычисляется** из опций (`analysis/compare.py::chain_status`), показан в UI
  и едет с экспортом (`run_provenance.yaml`, аддитивные ключи `.npz`). Экспериментальные числа нельзя
  принимать за выход верифицированного двойника.
- **Причинность — свойство, а не недоделка (`SW-68`).** Бит-идентичность поток↔батч на стадии
  интеграторов **невозможна по конструкции**: батчевые интеграторы непричинны (theory-06 §3.6).
  Приёмка потока — калибровка и швы бит-в-бит плюс метрики в полосе в пределах 11 §7 **после
  прогрева**; до `warmed = true` числа не окончательны. По той же причине `integrator`,
  `spectrum_method` и `welch_*` помечены батч-только — в реальном времени их просто не существует.
- **Осознанные пустоты живого режима (`SW-72`).** В потоке на вкладке Live пусты кривая входа и панель
  детектора: у потока нет истины, выровненной по окну отображения, а снимок несёт восстановленные
  сигналы, не сырьё. Пропуски отсчётов производятся **только** в режиме реального темпа; в ускоренном
  счётчик показывает «н/д», а не «0». Бесконечный синтетический стимул пока достигается зацикливанием,
  и **стык помечается**, а не сглаживается (честная непрерывность — S-24, замысел).
- **Предсказанные пики — предсказание, а не измерение (`SW-70`).** `ExpectedPeaks` — отдельный
  артефакт, вычислимый **без записи вообще**, и намеренно не поле `VibrationResult`. Высоты `f₁`, `3f`
  и `IM2` сознательно **не заявляются** (`None`), значимость возвращает `None`, когда сравнение не
  определено. Ветви `mains`, `alias`, `f_mount` объявлены, но пусты. Сверять предсказания не с чем до
  записей Э-0 — это и есть шаг 1 протокола 20 §3, а не его прохождение.
- **Асимметрия окна (M-21, открыто).** Окно доходит до Welch-PSD (и через неё до полосного СКЗ и
  оценки ISO) и до потокового спектра, но **не** до амплитудного спектра при `spectrum_method="fft"`.
  Проброс сдвинул бы доминанты приёмок и все golden ⇒ это санкционированная смена контракта, не
  правка; асимметрия названа в подсказке к полю и вынесена карточкой, а не зачинена молча.

**Немоделируемое в v1** (L2/L3-проверок для этого нет — 19 §6): температура TCS/TCB (**M-05**, только
хуки), мультимода/мода 2+ (вклад `<0.5 %` в полосе). Нелинейная инверсия `>50g` (M-07) — вне v1.

**Поляризация — закрытое допущение, а не пробел (M-09, R-58).** Поляризация в v1 **не моделируется
осознанно**, с числовыми границами: в тракте нет поляризационно-селективных элементов; `η`
поляризационно-независима **точно** (вырожденная пара мод LP₀₁); классический polarization fading
двухплечевых интерферометров **неприменим** — схема общего пути; внутриполосный канал (изгибное
двулучепреломление консоли @50g) подавлен на 7–8 порядков; остальные каналы ≤0.2 % (семейство) / ≤1.2 %
(`proto_poc`) и лежат на тепловых временах (под AC-связью). Пол RIN зависит от степени поляризации как
`RIN = RIN_пол·(1+DOP²)/2`; принятая конвенция `κ = 2` (поляризованная) — **консервативная верхняя
граница**, поэтому параметр `DOP` **намеренно не вводится** (иначе — понижение пола «по предположению»
и даблкаунт с измеренным RIN). **Единственная небезобидная оговорка:** дефолт `cmrr_db = 40` при
статическом балансе и посредственном ответвителе (PDL 0.1 дБ ⇒ качание деления ~2.3 %) **оптимистичен** —
пол статического CMRR ≈ 33 дБ; штатная митигация — авто-балансный приёмник, измеренное значение
вписывается в `cmrr_db` (D-07). Границы, ломающие допущение: поляризационно-селективный элемент в
тракте; **голый (неметаллизированный) цилиндр** (диатенюация до ~3 %); измеренный `DOP < 0.5` при NEA
впритык к полу RIN.

**Стендовая реализуемость (граница валидации, не модели).** Требование «50g на любой частоте полосы»
дословно нестендуемо: на 0.1 Гц это `x_pk≈1242 м`. Прямой гармонический 50g реализуем в окне
`≈50 Гц – 5 кГц`; НЧ — эквивалентами (центрифуга + перенос линейности), ВЧ 20 кГц — только пьезо +
лазерная виброметрия. Разнесение проверки — 20 §0(а)/§4.6.

**Вскрытый физдефект — пример работающего процесса (не тревога).**
При выводе блока `03_photodetection` слоя `docs/theory/` вскрыта опечатка **единицы** «ускорительной»
массы `M_a` в 07 §2: значение `M_a(1.4 мм)=0.58ρSL=2.19·10⁻⁸ кг` было подписано «≈22 нг», тогда как
это `≈22 мкг` (×1000, «нг» вместо «мкг»). **Значение в СИ и все производные `NEA_th` — верны;**
ошибочна только скобочная подпись. Дефект **не «тихо починен»**, а проведён процессом: зафиксирован
как решение **06 R-45** и внесён в первоисточник 07 координацией. Реализация `NEA_th` (M-12) позже
воспроизвела репер кодом: `M_a(1.4 мм) = 2.191·10⁻⁸ кг = 21.9 мкг` (R-52) — правка подтверждена
независимо. Это единственный физдефект за все блоки слоя — иллюстрация того, что маршрут
«вывод → решение → тест» работает.

**Перед работой с реальным датчиком.** L3 не пройден — сначала: фаза 0 (характеризация прототипа,
20 §1, снятие плейсхолдеров `proto_poc`), качественные предсказания **E1-P1…P6** (19 §3.2, доступны без
